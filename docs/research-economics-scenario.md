# M4.4 offline economics scenarios

`researchEconomicsScenario.ts` is a pure calculator, not a rate card, admission gate, tokenizer, invoice calculator or entitlement service. It imports only economics constants and arithmetic helpers. No existing activation or execution path consumes it. Outputs are deeply frozen and contain no execution authorization.

`PROVISIONAL_ECONOMICS_SCENARIO` records user-supplied assumptions: Apify $0.008 per billed listing and $0.00005 per start; OpenRouter Standard $0.25/M input and $1.50/M output tokens. It is provisional, non-activatable and activation-blocked. One billed unit per requested listing and one start per Apify attempt are assumptions, not verified billing. `includeInDemand` is disabled in this scenario, with no implied mapping to an actual actor request.

Unknown demand charges, failed-run billing and provider surcharges have null costs and are explicitly excluded. Every output retains `totalCostComplete:false`; no unknown category is assigned zero. Infrastructure, fees, support, taxes and acquisition are also excluded. Even a positive margin result is conditional on included costs only, not a guarantee of actual profitability.

## API and formulas

- `calculateResearchEconomicsScenario({pages, requestedListings?, inputTokens?, outputTokens?, apifyAttempts?, openrouterAttempts?})`: pages 1–3, listings 1–36 per requested page. Listings default to the full page count; tokens default to the hard ceilings. Token counts are explicit scenario assumptions, not measured usage. Input range is 0–33,280; output range is 0–2,048. Zero represents a cost component, not a dispatchable request. Attempts independently default to **one**, with only one or two accepted; this does not change SQL's two-attempt reserve policy.
- `auditEconomicsScenarioCatalog(options?)`: same token/attempt options, full requested listings. Enumerates every unordered nonnegative mix `n1 + 2*n2 + 3*n3 = credits` for the fixed proposed catalog (Starter $12/10, Growth $29/25, Pro $59/55, Business $99/90). Search order does not affect additive costs. Returns every mix and best/worst cost witnesses. Margins are exact profit/revenue integer ratios; 70% decisions use BigInt cross-multiplication, not rounded percentages. No production tiers are created or changed.
- `calculateEconomicsScenarioTrial({eligibleUsers,globalBudgetMicroUsd,...options})`: assumes one full one-page search per eligible user. Returns single-attempt and full-reserve totals plus floor-based capacities excluding unknown costs. The existing budget-only capacity fields retain their meanings. The additional fields cap those capacities by the supplied eligible-user count: `singleAttemptEligibleCapacity = min(eligibleUsers, singleAttemptCapacityExcludingUnknownCosts)` and `reservedEligibleCapacity = min(eligibleUsers, reservedCapacityExcludingUnknownCosts)`. These are offline estimates, not authorization to grant trials or spend money. The calculator does not establish eligibility or grant credits. A budget capacity is not a safe live enrollment limit without uncertainty buffers and atomic reservations.

All monetary outputs are integer micro-USD. `A=50+8000*listings`; `M=ceil(inputTokens*250000/1000000)+ceil(outputTokens*1500000/1000000)`. Single cost is `A+M`; reserve is `a*A+o*M`; additional retry reserve is `(a-1)*A+(o-1)*M`. Each token component rounds upward separately through the existing helper. Input ceiling is exactly `512+ceil((96*1024)/3)=33280`; model cost at both ceilings is 11,392 micro-USD. No per-search cent rounding is applied.

At 36/72/108 listings, single costs are $0.299442/$0.587442/$0.875442; two attempts each reserve $0.598884/$1.174884/$1.750884. All exceed the unchanged $0.12-per-credit cap, flagged on outputs rather than overridden. Lower-listing scenarios can fit that cap; that is not authorization. Trial cost for 1,000 users is $299.442 single / $598.884 double; a $100 budget floors to 333 / 166 trials before unknown charges.

Baseline catalog cost ranges are $2.925768–$2.994420, $7.302978–$7.486050, $16.057398–$16.469310 and $26.263260–$26.949780. Worst-case included-cost margins are about 75.05%, 74.19%, 72.09% and 72.78%. Repeated paid failures/refunded credits, extra starts, demand enrichment and unverified billing can invalidate these margins. Two-attempt reserves are liabilities, not forecasts or permission to retry.

## Validation and boundaries

Plain records only, exact allowed fields, no accessors/callbacks, safe integer counts, bounded pages/listings/tokens/attempts. Present undefined/null options are rejected. Trial counts and micro-USD budgets are nonnegative safe integers; aggregate products use BigInt and reject overflow rather than round. Catalog enumeration is bounded by the fixed proposed credit counts. Errors have fixed typed messages. Inputs are inert data, not a sandbox for hostile JavaScript proxies.

Tests cover all retry combinations, independent exhaustive plan mixes, rounding, cap flags, trial floors, overflow, malformed input, immutability and execution isolation. Run TypeScript, the existing suite and M3.6 `--static`. Verification of actual schemas, billing, failed-run charges, pricing dates, sufficient reservations, provider-reported usage and invoice reconciliation remains required before any separately authorized integration. Active rate cards, SQL, routes, provider adapters, entitlements and credit balances remain unchanged.
