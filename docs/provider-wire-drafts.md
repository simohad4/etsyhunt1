# M4.5 B2 offline wire drafts

These pure modules are separate from, and do not change, M4.2 adapters. They return deeply frozen descriptors/projections, never send requests, and never authorize admission, retries, billing or completion. Every result carries activationBlocked=true, executionAuthorized=false, automaticRetryAllowed=false, liveWireCertified=false and synthetic_unverified trust. They are **not live-wire certified**. Evidence and unresolved conflicts are recorded in [the dated manifest](provider-contract-evidence-2026-10-24.md).

## Apify

`buildApifyWireDraft(input)` delegates the research request to M4.2 and maps one keyword to queries, pages to maxPages and maximumListings to maxResults. Application caps remain 3 pages/108 listings. Sort/country and boolean policies are fixed, not caller-overridable. URL-like keywords are rejected. No endpoint, client, credentials or actor build is supplied.

`mapApifyWireDraft(rawJson,input,collectedAt,completion)` accepts a synthetic raw dataset array of only listingId/listingUrl/title/shopName/price/currencyCode. Numeric IDs must be positive safe integers and exactly agree with canonical listing URLs. Duplicate IDs reject. Numeric prices convert through JavaScript's canonical decimal string with no rounding; exponents, negatives, more than four fractional digits and values beyond existing projection range reject. This is a deliberately restrictive decimal policy, not a claim about actor precision. Currency must be explicit uppercase three-letter syntax; ISO membership is not certified. Price and currency must both be supplied or both missing/null. Missing observations remain unavailable. Extra raw fields are unsupported and rejected, even if the actor documents them.

The completion argument is an **application-owned synthetic test assertion**, not a new actor-wire field or verified run-status mapping. Only literal complete and exactly maxResults rows qualify for validated_fixture. Short, empty, partial or unknown datasets stay blocked; legitimate early exhaustion is deliberately unsupported rather than guessed. No amount of row validation proves actual run success. The projection is revalidated through the unchanged M4.2 validator. Run identity, pagination summaries, dataset continuation, partial errors, billed units and trustworthy timestamps remain unsupported.

Rejecting extra fields and incomplete datasets is deliberate offline-only behavior, not a claim of general actor compatibility. For example, even the documented `inCartCount` field rejects the entire row; it is never silently dropped. A separately verified full raw schema and reviewed mapping policy are required before broadening this subset.

## OpenRouter

`buildOpenRouterWireDraft(contextJson,maximumOutputTokens?)` delegates context validation to M4.2 and creates a nonstreaming body with the pinned model, existing messages, max_completion_tokens and strict JSON schema. The schema covers the existing projection's **content portion** (schemaVersion/interpretations); model, finish status and usage are copied only from validated envelope metadata, never invented by the model. Listing references are enumerated; narratives max 2000 characters; arrays max the context size. This narrower draft requires at least one interpretation. Duplicate references are rejected by M4.2 even though the JSON schema alone cannot guarantee reference uniqueness. Full serialized body and response are byte-bounded using existing limits.

Routing is an explicit proposed policy: only google-ai-studio, no fallbacks, require_parameters=true. The exact endpoint/slug and schema-keyword enforcement are not live-verified (`routingPolicyVerified:false`); do not activate based on this descriptor. No extra tools/plugins or paid price assumptions are added. The retained estimatedInputTokens is the existing M4.2 planning heuristic, not a tokenizer for the complete wire request/schema or actual billing. Future admission must reserve sufficient budget independently and reconcile actual usage.

JSON Schema support and routing controls are documented by the providers, but this exact schema and routing policy have not been live-tested. The generated descriptor contains no credentials, Authorization headers, endpoint or transport execution instructions. Tests assert root/item `additionalProperties:false`, required properties, listing-ID enums, array bounds and routing/output limits directly; these offline assertions do not certify upstream enforcement.

`mapOpenRouterWireDraft(rawJson,contextJson,generatedAt,maximumOutputTokens?)` accepts only a narrow nonstreaming envelope: id/object/created/model/choices/usage, or error. IDs must match a bounded gen-/chatcmpl- identifier grammar (a conservative local restriction, not a complete provider ID schema). One choice at index zero, assistant role, stop finish and JSON content are required. Native finish reasons are bounded metadata, not authority. Refusals and other normalized finish reasons block. Top-level/choice errors produce fixed PROVIDER_ERROR without raw details. Unknown transport outcomes have no success representation; this module does not dispatch or resolve them.

prompt_tokens and completion_tokens must be nonnegative safe integers within economics/output limits; total_tokens must equal their sum. Missing usage never becomes estimated usage. Optional provider cost/token breakdowns, system fingerprints, tools, streaming and extra envelope fields are intentionally unsupported and rejected. A complete official response may therefore be rejected until separately reviewed support is added. Existing adapter validation verifies content references and modeled provenance. Response IDs remain syntactic fixture metadata, not proof of identity binding, ownership or provider idempotency. Timestamps remain caller-supplied, not matched against a real attempt.

## Trust, tests and remaining blockers

Tests contain synthetic fixtures only. Prompt-injection text can remain in a structurally valid modeled narrative: local validation guarantees structure, not truth or safety of natural language. Keep synthetic trust labels attached, render text safely, and do not log sensitive payloads. Existing byte limits run before JSON parsing, but a future transport must also bound network buffering/decompression. Inputs are inert JSON-like data, not a hostile-JavaScript sandbox. Standard JSON.parse retains the last duplicate object key; rejecting duplicate keys remains a separate raw-parser hardening decision. Decimal lexical fidelity cannot be recovered after parsing a JSON number.

Frozen result wrappers retain synthetic_unverified trust and cannot be changed to live or authorized in place. Payload-supplied live/provenance assertions are rejected as unsupported fields. Nested observed labels describe fixture-supplied values only; callers must not detach that data from its synthetic wrapper and publish it as live evidence. Freezing is not an authenticity mechanism and cannot prevent a caller from constructing an unrelated object.

Before any executor: pin actor build/schema evidence, resolve full raw nullability/precision and completion semantics, verify routing/structured-output capabilities, obtain verified pricing including unknown demand/failed-run/surcharge costs, resolve the existing spending-cap mismatch, and implement authoritative owner/attempt admission, durable dispatch identity, explicit retry authorization and ambiguity reconciliation. No SQL, route, credit logic, active pricing or legacy analyzer changes belong to these drafts. Run TypeScript, the existing test suite, M3.6 --static and git diff --check; never substitute a live test for offline checks.
